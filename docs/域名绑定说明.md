# 免费二级域名绑定 GitHub Pages 说明

> 本文件仅给项目管理员看，不加入站点导航，也不对外公开。
> 当前**先不要**创建 `CNAME` 文件，未获批域名前加了会导致 GitHub Pages 站点 404。

## 一、推荐方案对比

| 方案 | 类型 | 费用 | 审核 | 适合场景 |
|---|---|---|---|---|
| **js.org** | 免费二级域 `<name>.js.org` | 永久免费 | GitHub PR 人工审核，通常数天 | 开源项目，审核较友好 |
| **eu.org** | 永久免费二级域 `<name>.eu.org` | 永久免费 | 人工审核，可能数天到数周 | 想要更正式的二级域 |
| Cloudflare / 自家域名 | 任意顶级域 | 需买域名 | 即时 | 愿意花钱时 |

下面给出 js.org 与 eu.org 的可执行步骤。

---

## 二、js.org（推荐先试）

### 1. 申请条件
- 仓库为公开开源仓库（本仓库 `ETQWFD/HNN-CN-ET` 满足）。
- 站点已经能在默认地址 `https://etqwfd.github.io/HNN-CN-ET/` 正常访问。
- 申请的子域名与项目相关。

### 2. 步骤
1. 在仓库根目录（或 `docs/`，与 GitHub Pages 发布根一致）新建文件 `CNAME`，内容**仅一行**：
   ```
   hnn.etqwfd.js.org
   ```
   （域名可自定，例如 `hnn-cn-et.js.org`、`et-llm.js.org`，注意 js.org 要求项目名/域名相关）
2. 提交并 push 到 `main`，确认 `https://etqwfd.github.io/HNN-CN-ET/` 仍能访问（CNAME 生效前 GitHub 会自动用 CNAME 内的域名服务）。
3. Fork 仓库 `https://github.com/js-org/js.org`。
4. 在你 fork 的仓库里编辑 `cnames_active.js`，在数组末尾按字母顺序加一行：
   ```js
   "hnn-et": "ETQWFD.github.io/HNN-CN-ET",
   ```
   （键是 `hnn-et`，对应 `hnn-et.js.org`；值是你的 GitHub Pages 主机 + 仓库路径）
5. 提交 Pull Request 到 js-org/js.org，PR 说明里写明项目简介、为什么用这个子域。
6. 等待审核合并。合并后 js.org 的 DNS 会自动把 `hnn-et.js.org` CNAME 到 `ETQWFD.github.io`。
7. 回到 GitHub 仓库 → **Settings → Pages → Custom domain**，输入 `hnn-et.js.org`，勾选 **Enforce HTTPS**。
8. 等待 DNS 验证通过（几分钟到几十分钟）。

### 3. 注意
- CNAME 文件必须在 GitHub Pages 发布根目录。本仓库从 `main` 分支 `/docs` 发布，所以 CNAME 放在 `docs/CNAME`。
- 不要同时把同一个 CNAME 放到多个分支。

## 三、eu.org

### 1. 申请
1. 打开 https://nic.eu.org/ 注册一个账号（用邮箱接收验证）。
2. 申请一个 `<name>.eu.org` 二级域（例如 `hnn-cn-et.eu.org`）。
3. 申请时需要填写 NS 记录或 A/CNAME 记录。eu.org 审核较慢，通常要求：
   - 站点已经能正常访问；
   - 域名用途与项目匹配；
   - 有真实邮箱联系人。

### 2. 接入 GitHub Pages
获批后有两种做法：

**做法 A：直接用 CNAME（推荐，最简单）**
1. 在 `docs/CNAME` 里写：
   ```
   hnn-cn-et.eu.org
   ```
2. 到 eu.org 的 DNS 管理面板，把该域名的 CNAME 指向：
   ```
   ETQWFD.github.io.
   ```
   （末尾的点不能少）
3. 回 GitHub 仓库 → Settings → Pages → Custom domain 填 `hnn-cn-et.eu.org`，勾选 Enforce HTTPS。

**做法 B：用 Cloudflare 中转**
1. 在 Cloudflare 申请免费账号，添加站点 `hnn-cn-et.eu.org`（需要先把 eu.org 分配的 NS 改成 Cloudflare 的 NS）。
2. 在 Cloudflare DNS 里加一条 CNAME：
   ```
   @  CNAME  ETQWFD.github.io
   ```
   （代理状态：仅 DNS / 橙色云都可；第一次建议先灰云纯 DNS，验证通过再开橙云）
3. Cloudflare SSL/TLS 模式设为 **Full** 或 **Full (strict)**。
4. GitHub 仓库 Settings → Pages → Custom domain 填同样的域名，勾 Enforce HTTPS。

## 四、通用收尾（无论哪个域名）

1. 仓库 `docs/CNAME` 内容 = 你最终要用的域名（仅一行，无空格）。
2. GitHub 仓库 → **Settings → Pages**：
   - Source: `Deploy from a branch`（或由 GitHub Actions 自动发布）
   - Branch: `main` / folder: `/docs`
   - Custom domain: 填你的域名
   - 勾选 **Enforce HTTPS**
3. 等几分钟到几十分钟，DNS 生效后访问 `https://<你的域名>/` 应能打开本站。
4. 本地开发时 hosts 可以先指到 `185.199.108.153`（GitHub Pages 的任一 IP）验证。
